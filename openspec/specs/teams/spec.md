## Purpose

사용자가 팀을 만들거나 초대코드로 합류하여 하나의 팀에 소속되도록 하고, 팀 소속 여부에 따라 칸반/채팅 접근을 통제한다.

## Requirements

### Requirement: 1인 1팀 제약
시스템은 각 사용자가 동시에 최대 하나의 팀에만 소속되는 것을 SHALL 강제한다(`users.team_id`). 팀에 소속되지 않은 사용자는 `team_id`가 NULL이며 칸반/채팅에 접근할 수 없다.

#### Scenario: 미가입 사용자의 칸반 접근 시도
- **WHEN** `team_id`가 NULL인 사용자가 `/teams/*` 하위 리소스에 접근을 시도한다
- **THEN** 시스템은 팀 선택 화면으로 유도하며 해당 리소스를 반환하지 않는다

### Requirement: 팀 생성
시스템은 인증된 사용자가 새 팀을 만드는 것을 SHALL 지원한다. 생성자는 자동으로 해당 팀의 owner가 되고, 서버가 고유한 초대코드(대문자 4자 + '-' + 숫자 4자)를 자동 생성한다.

#### Scenario: 정상 팀 생성
- **WHEN** 소속 팀이 없는 사용자가 1-30자 팀 이름으로 `POST /teams`를 호출한다
- **THEN** 시스템은 201로 팀을 생성하고, 생성자를 owner로 지정하고, `users.team_id`를 갱신하고, 초대코드를 응답에 포함한다

### Requirement: 초대코드로 합류
시스템은 사용자가 유효한 초대코드로 기존 팀에 합류하는 것을 SHALL 지원한다. 초대코드는 팀당 1개로 고정되며 재발급되지 않고, 팀을 나간 뒤에도 동일한 코드로 재합류할 수 있다.

#### Scenario: 정상 합류
- **WHEN** 소속 팀이 없는 사용자가 존재하는 초대코드로 `POST /teams/join`을 호출한다
- **THEN** 시스템은 200과 함께 `users.team_id`를 해당 팀으로 갱신하고 팀 정보를 반환한다

#### Scenario: 형식 오류
- **WHEN** 사용자가 `^[A-Z]{4}-[0-9]{4}$` 형식에 맞지 않는 코드를 입력한다
- **THEN** 시스템은 400 `VALIDATION_ERROR`를 반환한다

#### Scenario: 존재하지 않는 코드
- **WHEN** 사용자가 형식은 유효하지만 존재하지 않는 코드를 입력한다
- **THEN** 시스템은 404 `NOT_FOUND`를 반환한다

#### Scenario: 이미 다른 팀 소속
- **WHEN** 이미 다른 팀에 소속된 사용자가 합류를 시도한다
- **THEN** 시스템은 409 `EMAIL_TAKEN` 계열이 아닌 충돌 오류를 반환하며, 먼저 기존 팀을 나가야 함을 안내한다

### Requirement: 팀 나가기
시스템은 팀에 소속된 사용자가 스스로 팀을 나가는 것을 SHALL 지원한다. 나간 사용자는 `team_id`가 NULL로 초기화되고, 팀의 초대코드는 변경되지 않으므로 동일한 코드로 재합류할 수 있다.

#### Scenario: 정상 나가기
- **WHEN** 팀에 소속된 사용자가 `DELETE /teams/{id}/leave`를 호출한다
- **THEN** 시스템은 200을 반환하고 해당 사용자의 `team_id`를 NULL로 설정한다

### Requirement: 팀 정보 조회
시스템은 팀 소속 멤버가 자신이 속한 팀의 정보(이름, 초대코드, owner)를 언제든 다시 조회하는 것을 SHALL 지원한다. 팀 생성 직후 1회성으로만 노출되지 않고, 이후에도 초대코드를 다시 확인할 수 있어야 한다.

#### Scenario: 팀 정보 재조회
- **WHEN** 팀 소속 사용자가 `GET /teams/{id}`를 호출한다
- **THEN** 시스템은 200과 함께 팀 이름, 초대코드, owner_id를 반환한다

### Requirement: 팀 멤버 목록 조회
시스템은 팀 소속 멤버가 자신의 팀 멤버 목록(owner/member 구분 포함)을 조회하는 것을 SHALL 지원한다.

#### Scenario: 멤버 목록 조회
- **WHEN** 팀 소속 사용자가 `GET /teams/{id}/members`를 호출한다
- **THEN** 시스템은 200과 함께 멤버별 이메일, 역할(owner/member), 가입 시각을 반환한다

### Requirement: 비멤버 접근 차단
시스템은 팀 멤버가 아닌 사용자가 `/teams/{id}/*` 하위 리소스(칸반, 채팅, 멤버 목록 포함)를 조회하거나 변경하는 모든 시도를 SHALL 차단한다.

#### Scenario: 다른 팀 리소스 직접 접근
- **WHEN** 유효한 JWT를 가졌지만 해당 팀 멤버가 아닌 사용자가 `GET/POST/PATCH/PUT/DELETE /teams/{id}/*`를 호출한다
- **THEN** 시스템은 403 `FORBIDDEN`을 반환한다
