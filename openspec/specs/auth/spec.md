## Purpose

사용자가 이메일과 비밀번호로 계정을 만들고 로그인하여, 이후 모든 팀/칸반/채팅 API 호출에 사용할 신원 증명(JWT)을 얻도록 한다.

## Requirements

### Requirement: 회원가입
시스템은 이메일과 비밀번호로 신규 계정 생성을 SHALL 지원한다. 이메일은 형식이 유효해야 하고 중복될 수 없으며, 비밀번호는 8자 이상이어야 하고 bcrypt로 해시되어 저장되어야 한다. 이메일 인증 절차는 없으며 가입 즉시 계정이 활성화된다.

#### Scenario: 정상 가입
- **WHEN** 사용자가 형식이 유효하고 미사용중인 이메일과 8자 이상 비밀번호로 `POST /auth/signup`을 호출한다
- **THEN** 시스템은 201과 함께 JWT를 발급하고 사용자를 생성한다

#### Scenario: 이메일 형식 오류
- **WHEN** 사용자가 이메일 형식이 아닌 값으로 가입을 시도한다
- **THEN** 시스템은 400 `VALIDATION_ERROR`를 반환한다

#### Scenario: 이메일 중복
- **WHEN** 사용자가 이미 가입된 이메일로 가입을 시도한다
- **THEN** 시스템은 409 `EMAIL_TAKEN`을 반환한다

#### Scenario: 비밀번호 약함
- **WHEN** 사용자가 8자 미만 비밀번호로 가입을 시도한다
- **THEN** 시스템은 400 `VALIDATION_ERROR`를 반환한다

### Requirement: 로그인
시스템은 이메일과 비밀번호로 로그인하여 24시간 유효한 JWT를 발급하는 것을 SHALL 지원한다. 인증 실패 시 이메일 존재 여부를 노출하지 않고 동일한 오류 메시지를 반환해야 한다.

#### Scenario: 정상 로그인
- **WHEN** 사용자가 올바른 이메일/비밀번호로 `POST /auth/login`을 호출한다
- **THEN** 시스템은 200과 함께 24시간 만료 JWT 및 사용자 정보(`team_id` 포함)를 반환한다

#### Scenario: 자격 증명 오류
- **WHEN** 사용자가 존재하지 않는 이메일이거나 비밀번호가 틀린 상태로 로그인을 시도한다
- **THEN** 시스템은 401 `INVALID_CREDENTIALS`를 반환하며 이메일 존재 여부는 응답에서 구분되지 않는다

### Requirement: 로그아웃
시스템은 JWT가 stateless임을 전제로, 서버 측 토큰 블랙리스트 없이 로그아웃을 SHALL 지원한다. 클라이언트가 토큰을 폐기하는 방식이며 토큰은 만료 전까지 유효할 수 있다.

#### Scenario: 로그아웃 호출
- **WHEN** 인증된 사용자가 `POST /auth/logout`을 호출한다
- **THEN** 시스템은 200과 빈 응답을 반환하고, 서버는 해당 토큰을 무효화하지 않는다

### Requirement: 세션 만료 처리
시스템은 만료되거나 없는 JWT로 보호된 엔드포인트를 호출하면 401을 SHALL 반환한다. 토큰 갱신(refresh) 기능은 제공하지 않는다.

#### Scenario: 만료 토큰으로 API 호출
- **WHEN** 사용자가 만료된 JWT로 보호된 엔드포인트를 호출한다
- **THEN** 시스템은 401 `TOKEN_EXPIRED`를 반환한다

### Requirement: 현재 사용자 조회
시스템은 인증된 사용자가 자신의 계정 정보(이메일, `team_id` 등)를 조회하는 것을 SHALL 지원한다.

#### Scenario: 내 정보 조회
- **WHEN** 인증된 사용자가 `GET /auth/me`를 호출한다
- **THEN** 시스템은 200과 함께 해당 사용자의 id, email, team_id를 반환한다
